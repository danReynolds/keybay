# SDK and CLI 0.3.2 publication, October 18, 2026

[Keybay SDK 0.3.2](https://pub.dev/packages/keybay/versions/0.3.2) and
[CLI 0.3.2](https://github.com/danReynolds/keybay/releases/tag/keybay_cli-v0.3.2)
are published from one commit, with signed tags. They move to
[Keypass 0.1.0-dev.3](https://pub.dev/packages/keypass/versions/0.1.0-dev.3),
which builds desktop hardware support against OpenSSL 3 or 4. The vault format
is unchanged from 0.3.0.

## Why this release

Homebrew rebuilt libfido2 1.17.0 against OpenSSL 4 on October 8, 2026, and
Keypass 0.1.0-dev.2 refused to bundle `libcrypto.4`. Desktop builds of the SDK
and CLI on a current Homebrew therefore failed. Keypass 0.1.0-dev.3
([keypass#7](https://github.com/danReynolds/keypass/pull/7), commit `000988d`,
published `2026-10-17T23:40:55Z`) accepts OpenSSL 3 or 4 and still refuses two
different libcrypto versions.

- **Keypass CI:** it asserted that Homebrew's libfido2 links `libcrypto.4`, built
  the adapter against OpenSSL 4.0.3, and bundled `libcrypto.4`.
- **Keybay PR #112:** its macOS jobs ran the full SDK suite on that libfido2.
- **Keybay pin:** Keybay pins Keypass's hosted archive `e11a551b…`.
  `tool/keypass-source.json` lists the native build inputs, each matching Keypass
  commit `000988d`.

## Bundled OpenSSL

The macOS archive was built on a host whose libfido2 links Homebrew `openssl@3`
3.5.9, so it bundles OpenSSL 3.5.9 (29 Sep 2026), patched for that month's
advisory. The Linux archives bundle Ubuntu 22.04's `libssl3`
`3.0.2-0ubuntu1.30`, still the current package for that release on October 18.
