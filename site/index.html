Five-command CLI · macOS · Linux desktop

Keep secrets
out of Git.

Commit your non-secret config and kb:// references. Keybay keeps the values in an OS-protected local store, then gives your app the environment it already expects. No Keybay account or hosted service. No Keybay daemon, network path, or shell hook.

Keybay V2 is pre-1.0. The API and encrypted format may still change while the cross-platform provider matrix is qualified.

Keybay example app started.
  API_URL: https://staging.example.com

The CLI is one application with one encrypted store. Slash-separated names organize records; they do not isolate them. When you use run, only referenced values are passed to the child process as environment variables.

Dart / Flutter SDK

Use Keybay inside your app.

Open the host application's one store, then read and write values directly. Keybay derives identity and handles storage on iOS, Android 12+, macOS, and ordinary Linux desktop.

SDK quickstart →

Dart

import 'package:keybay/keybay.dart';

final session = await Keybay.open();
try {
  await session.set('api-token', tokenFromOAuth);
  final stored = await session.get('api-token');
} finally {
  await session.close();
}

How Keybay stores data on each platform.

Keybay makes the storage choice for you, using one documented policy for each runtime.

ContextStored asProtected by
SDK · iOSEncrypted framed fileRoot in the exact signed Data Protection Keychain group
SDK · Android 12+Encrypted framed fileOne non-exportable Android Keystore key
SDK · entitled macOSEncrypted framed fileRoot in the exact signed Data Protection Keychain group
SDK/CLI · unentitled macOSEncrypted framed fileOne root item in the login Keychain
SDK/CLI · Linux desktopEncrypted framed fileOne root item in an unlocked Secret Service provider

Desktop credential stores must be available and unlocked. Keybay does not attest Apple hardware backing; on Android it reports the wrapping-key security level it actually observes.

Windows, Flatpak, Snap, and unsupported/headless configurations currently fail closed.

What Keybay protects—and what it doesn't.

Full security design →
Fails closed
If the required store is unavailable, locked, invalidated, corrupt, tampered with, or unsupported, Keybay stops. It never substitutes plaintext.
Encrypted, coordinated writes
Each record is independently XChaCha20-Poly1305 encrypted. Writes authenticate the source and atomically replace one complete framed file.
Only claims it can verify
Provider and device qualification reports only measured properties. Keybay makes no Secure Enclave claim for generic Apple Keychain items.
Protection has a boundary
After your app reads a value—or run adds it to a child environment—it is ordinary process data. Same-user malware, rollback, and root remain outside the threat model.

Local by design.

Keybay is for secrets that belong on one device. Every host application, including the CLI, has one local store derived from its application identity. Keybay does not sync secrets, distribute them to a team, or provision production systems.
